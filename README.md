# sim800-capabilities

[![Tests](https://img.shields.io/badge/tests-pytest-green.svg)](https://docs.pytest.org/)
[![Data-driven](https://img.shields.io/badge/data--driven-YAML-orange.svg)](https://yaml.org/)

Data-driven capability database for the SIM800 family of modules. All
capability data lives in YAML under `data/`, is validated against JSON
Schema under `schema/`, and is queried/compared/generated by the Python
package under `src/sim800_capabilities/`. Nothing is hard-coded in the code.

## Scope

Models: `SIM800`, `SIM800A`, `SIM800C`, `SIM800C-DS`, `SIM800F`, `SIM800H`,
`SIM800L`, `SIM808`, `SIM868`.

Capabilities: `bands`, `data_features`, `gprs`, `bluetooth`, `gpio`, `adc`,
`pcm`, `usb`, `sim_interface`, `uart_serial`, `gnss`, `environmental`,
`power`.

Out of scope: `audio`, `keypad`, `spi`, `i2c`, `sd`, `camera`, `fm`,
`charging`, `dimensions`, `antenna`.

## Layout

```
data/
  capabilities.yaml     # generated artifact (do not edit by hand)
  sources.yaml          # source registry
  scope.yaml            # models + in/out of scope capabilities
  out-of-scope.yaml     # out-of-scope entries with reasons
  models/*.yaml         # per-model capability files
schema/                 # JSON Schema for every data file
src/sim800_capabilities/# loader, validator, query, compare, generate, audit, cli
tests/                  # unit + regression tests
docs/                   # extraction, conflict, provenance notes
```


## Common commands

```powershell
sim800-capabilities validate
sim800-capabilities list --format json
sim800-capabilities show SIM800
sim800-capabilities get SIM800 capabilities.bands.type --value-only
sim800-capabilities find sim80
sim800-capabilities compare SIM800 SIM800L
sim800-capabilities export --format csv  > capabilities.csv
sim800-capabilities generate
sim800-capabilities audit --format json
sim800-capabilities conflicts --unresolved-only
```

A C++ header for firmware consumption can be generated from the same YAML
sources (single source of truth):

```powershell
sim800-capabilities generate --target cpp
sim800-capabilities generate --target all
sim800-capabilities export --format cpp > sim800_capabilities.hpp
```

By default the header is written to `include/sim800_capabilities.hpp`; use
`--out <path>` to override. The header is header-only, dependency-free, and
uses only `constexpr` C++17 constructs.

Exit codes: `0` success, `1` input/data error, `2` internal error.

## Adding a new model

1. Add the model name to `data/scope.yaml` -> `models` and to `family_map`.
2. Add a dedicated Hardware Design source to `data/sources.yaml`.
3. Create `data/models/<model_lowercase>.yaml` following the FieldValue
   shape documented in `docs/provenance.md`.
4. Run `sim800-capabilities validate` then `sim800-capabilities generate`.

## Rules

- Only `data/models/*.yaml` is hand-edited.
- `data/capabilities.yaml` is regenerated by `generate`.
- Every value carries `status`, `source_id`, `source_ref`, `confidence`.
- `not_documented` and `not_supported` are first-class and never confused.
